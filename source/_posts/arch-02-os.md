## 进程 vs 线程

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 资源 | 独立地址空间、文件、内存 | 共享进程资源 |
| 切换开销 | 大（需切换页表等） | 小 |
| 通信 | IPC（管道、信号、共享内存、消息队列） | 共享内存，直接读写 |
| 崩溃影响 | 不影响其他进程 | 一个线程崩溃可能拖垮进程 |
| 并发粒度 | 粗 | 细 |

**进程三态模型**：
```
就绪(Ready) → 运行(Running)：调度
运行(Running) → 就绪(Ready)：时间片用完/被抢占
运行(Running) → 阻塞(Blocked)：等待I/O或资源
阻塞(Blocked) → 就绪(Ready)：I/O完成/资源可用
```

**五态模型**：在三态基础上加 新建（New）和 终止（Exit）

## 进程调度算法

| 算法 | 说明 | 特点 |
|------|------|------|
| FCFS | 先来先服务 | 简单，对长作业有利，对短作业不公平 |
| SJF | 短作业优先 | 平均等待时间最短，可能饥饿 |
| 优先级调度 | 按优先级高低 | 可抢占或不可抢占 |
| 时间片轮转（RR） | 每个进程分配固定时间片 | 公平，适合分时系统 |
| 多级反馈队列 | 多个优先级队列，高优先级时间片短 | 综合效果最好，现代OS常用 |
| 最高响应比优先（HRRN） | 响应比 = (等待时间+服务时间)/服务时间 | 兼顾长短作业 |

## 信号量与 PV 操作

```
P(S)：S = S - 1，若 S < 0，进程阻塞
V(S)：S = S + 1，若 S ≤ 0，唤醒一个等待进程
```

**互斥**：信号量初值为 1，P/V 包住临界区
**同步**：信号量初值为 0，表示"等待某事件发生"

**经典问题**：
- **生产者-消费者**：empty（空槽数）、full（满槽数）、mutex（互斥锁）
- **读者-写者**：读者优先 vs 写者优先
- **哲学家进餐**：防死锁策略（奇偶编号取筷、资源排序）
- **考点**：P操作顺序不能颠倒（先P资源信号量，再P互斥量），V顺序无所谓

## 死锁

**四个必要条件**（同时满足才会死锁）：
1. **互斥**：资源一次只能被一个进程使用
2. **占有并等待**：进程持有资源的同时等待其他资源
3. **不可抢占**：已分配的资源不能被强制剥夺
4. **循环等待**：进程之间形成等待环路

**处理策略**：

| 策略 | 方法 | 代价 |
|------|------|------|
| 预防 | 破坏四个条件之一 | 资源利用率低 |
| 避免 | 银行家算法，动态检测安全状态 | 需要预知资源需求 |
| 检测 | 资源分配图，定期检测 | 允许死锁发生，事后恢复 |
| 忽略 | 鸵鸟算法 | 适合死锁概率极低的场景 |

**银行家算法**：
- 核心：判断分配后系统是否处于**安全状态**（存在安全序列）
- 安全序列：按该顺序执行所有进程，每个进程都能获得足够资源完成

## 内存管理

**分区分配**：
- 固定分区：大小固定，内碎片严重
- 动态分区：按需分配，产生外碎片
- 最佳适配（Best Fit）：找最小的合适空闲区
- 最差适配（Worst Fit）：找最大的空闲区

**分页**：
- 将内存和逻辑地址空间都划分为等大的页（Page）
- 逻辑地址 = 页号 + 页内偏移
- 通过**页表**将页号映射到帧号（Frame）
- 无外碎片，有内碎片（最后一页）
- **TLB**（快表）：页表的高速缓存，提高地址转换速度

**分段**：
- 按逻辑模块（代码段、数据段、栈段）划分
- 逻辑地址 = 段号 + 段内偏移
- 无内碎片，有外碎片
- 便于共享和保护

**段页式**：先分段，再对每段分页，综合两者优点

## 页面置换算法

| 算法 | 说明 | 特点 |
|------|------|------|
| OPT（最优） | 替换未来最长时间不用的页 | 理论最优，不可实现 |
| FIFO | 替换最早进入内存的页 | 实现简单，可能有 Belady 异常 |
| LRU | 替换最近最久未使用的页 | 近似OPT，实现复杂 |
| LFU | 替换使用频率最低的页 | 不能反映最近的访问情况 |
| Clock（时钟） | 近似LRU，使用访问位 | 实际OS常用 |

**Belady 异常**：增加内存帧数反而导致缺页次数增加，只出现在 FIFO 中

**抖动（Thrashing）**：进程频繁缺页，大量时间花在换页上，CPU利用率急剧下降
- 原因：分配给进程的帧数少于工作集大小
- 解决：工作集模型、缺页频率控制

## 文件系统

- **FAT**（文件分配表）：链式存储，不支持随机访问
- **inode**（索引节点）：Unix/Linux 方案，存储文件元数据和数据块指针
  - 直接指针：直接指向数据块
  - 一级间接：指向指针块
  - 二级/三级间接：支持更大文件

**文件权限**（Linux）：读(r=4)、写(w=2)、执行(x=1)，分属主/组/其他

## I/O 管理

- **程序查询方式**：CPU轮询等待，效率最低
- **中断方式**：I/O完成后通知CPU，CPU利用率提高
- **DMA（直接内存访问）**：I/O设备直接与内存交互，不占用CPU，适合大数据量传输
- **通道方式**：独立的I/O处理器（通道），CPU只需发出I/O命令

**设备独立性**：应用程序通过统一接口访问设备，屏蔽底层差异（逻辑设备→物理设备的映射）
