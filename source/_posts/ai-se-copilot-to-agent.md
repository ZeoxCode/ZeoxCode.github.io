AI 编程工具大概经历了一个变化：从补全工具，到对话工具，再到 coding agent。

这几个东西看起来都叫 AI 编程，但工程含义不一样。

## Copilot 类工具

Copilot 更像“智能补全”。

特点：

- 在编辑器里补全当前代码。
- 适合写函数、样板代码、测试片段。
- 人仍然控制文件、结构和修改范围。

它像一个坐在旁边的副驾驶，主要帮你加速输入。

传统软件工程里，开发者仍是绝对主导。

## Chat 类工具

ChatGPT、Claude 这类对话工具，可以解释代码、生成方案、回答问题。

它们适合：

- 学习概念。
- 讨论设计。
- 生成代码片段。
- 分析报错。
- 写文档初稿。

但如果它不直接接入仓库，很多上下文要人复制粘贴，容易丢信息。

## Coding Agent

Coding Agent 更进一步。  
它可以读取仓库、搜索文件、修改多个文件、运行测试、根据结果继续调整。

这就不只是补全，而是参与一个小任务的执行闭环。

典型流程：

```text
理解任务 -> 搜索代码 -> 制定计划 -> 修改文件 -> 运行测试 -> 修复失败 -> 总结变更
```

这和传统软件工程差别很大，因为 AI 开始参与“开发过程”，而不只是生成代码片段。

## Agent 的好处

Agent 适合做：

- 跨文件重构。
- 补测试。
- 修简单 bug。
- 升级 API。
- 修改文档。
- 处理重复机械改动。

它的优势是可以保持任务上下文，并且根据工具结果调整。

## Agent 的风险

风险也更大：

- 修改范围变大。
- 可能误解任务。
- 可能为了通过测试改错地方。
- 可能删除重要逻辑。
- 可能引入新依赖。
- 运行命令和改文件需要权限控制。

传统 Copilot 错了，通常只错在当前几行。  
Agent 错了，可能影响整个仓库。

## 工程上怎么用 Agent

比较稳的方式：

- 任务要小。
- 边界要清。
- 先让它读代码和复述理解。
- 让它列修改计划。
- 一次只做一个目标。
- 必须看 diff。
- 必须跑测试。
- 重要改动要人工 review。

Agent 越强，流程越要严谨。

## 与传统软件工程的关系

传统软件工程强调任务拆解、版本控制、测试、review。  
这些在 agent 时代不是减少，而是变成安全框架。

没有这些框架，agent 就像一个很快但不一定可靠的实习生，能做很多事，也能制造很多麻烦。

key：

- Copilot 是补全，Agent 是执行任务。
- Agent 能跨文件工作，所以风险也更大。
- 小任务、强边界、测试和 review 是使用 Agent 的基本原则。
