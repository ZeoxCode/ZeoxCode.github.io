分治算法的复杂度经常写成递推式。

比如归并排序：

```text
T(n) = 2T(n/2) + O(n)
```

意思是：

- 分成两个规模为 `n/2` 的子问题。
- 合并需要 `O(n)`。

最后结果是：

```text
T(n) = O(n log n)
```

## 递归树理解

归并排序的递归树：

```text
第 0 层：n
第 1 层：n/2 + n/2 = n
第 2 层：四个 n/4，总和 n
...
```

每一层合并代价都是 `n`。  
一共 `log n` 层。

所以总复杂度：

```text
O(n log n)
```

这种理解比硬背公式更稳。

## 主定理

常见递推式：

```text
T(n) = aT(n/b) + f(n)
```

含义：

- `a`：子问题个数。
- `n/b`：子问题规模。
- `f(n)`：分解和合并的代价。

核心是比较：

```text
f(n) 和 n^(log_b a)
```

粗略记法：

1. 如果 `f(n)` 小很多，复杂度由叶子主导。
2. 如果 `f(n)` 差不多，复杂度多一个 `log n`。
3. 如果 `f(n)` 大很多，复杂度由每层合并代价主导。

## 例子

### 归并排序

```text
T(n) = 2T(n/2) + n
```

这里：

```text
a = 2, b = 2
n^(log_b a) = n
f(n) = n
```

相同，所以：

```text
T(n) = O(n log n)
```

### 二分查找

```text
T(n) = T(n/2) + 1
```

每次只进一个子问题，额外代价常数。

结果：

```text
O(log n)
```

### 普通递归求最大值

```text
T(n) = 2T(n/2) + 1
```

每层节点总数增长，最终总节点数量是 `O(n)`。

## 注意

主定理很好用，但不是万能。  
有些递推式不符合标准形式，比如：

```text
T(n) = T(n-1) + n
```

这种就要用展开法：

```text
n + (n-1) + ... + 1 = O(n^2)
```

key：

- 分治复杂度常写成递推式。
- 递归树能直观看每层代价。
- 主定理适合 `T(n)=aT(n/b)+f(n)` 这种形式。
