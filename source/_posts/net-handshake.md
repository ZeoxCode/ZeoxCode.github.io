三次握手和四次挥手很容易被背成口诀。
但真正要记的是：它们是在同步双方状态。

## 三次握手为什么是三次

建立 TCP 连接时，双方至少要确认两件事：

- 我能发送，你能接收。
- 你能发送，我能接收。

过程：

```
1. 客户端 -> 服务端：SYN
2. 服务端 -> 客户端：SYN + ACK
3. 客户端 -> 服务端：ACK
```

第一次：客户端告诉服务端，我想建立连接，我能发。
第二次：服务端告诉客户端，我收到了，你也能发，我也能发。
第三次：客户端告诉服务端，我收到了，你能发我也能收。

这样双方都确认了收发能力。

## 为什么不是两次

如果只有两次，服务端无法确认客户端是否收到了自己的 SYN+ACK。
也就是说服务端不知道客户端的接收能力是否正常。

还有一个经典问题：旧的连接请求如果在网络里延迟很久，后来又到了服务端，两次握手可能让服务端误以为要建立新连接。

三次握手可以减少这种错误连接的风险。

## 四次挥手为什么是四次

TCP 是全双工通信。
一方说“我不发了”，不代表另一方也不能继续发。

过程可以理解为：

```
1. A -> B：FIN，我这边不发了
2. B -> A：ACK，我知道了
3. B -> A：FIN，我也不发了
4. A -> B：ACK，我知道了
```

中间第二步和第三步不能总是合并，因为 B 可能还有数据没发完。

## TIME_WAIT 为什么存在

主动关闭连接的一方会进入 TIME_WAIT。

主要原因：

- 确保最后一个 ACK 能被对方收到。
- 让旧连接中的残留报文在网络中消失。

如果没有 TIME_WAIT，旧连接的报文可能影响新连接。

## 经典例题

**问题：为什么建立连接是三次，关闭连接常常是四次？**

建立连接时，服务端的 SYN 和 ACK 可以合在一起发。
关闭连接时，一方收到 FIN 后，只能说明对方不发了，但自己可能还有数据要发，所以 ACK 和 FIN 常常分开发。

## 不能忘的点

- 三次握手是为了确认双方收发能力。
- 四次挥手是因为 TCP 是全双工。
- TIME_WAIT 是为了处理最后 ACK 和旧报文残留问题。
