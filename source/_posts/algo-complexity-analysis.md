复杂度分析是算法课的底座。

代码能跑，不代表算法可用。  
如果数据规模只有 10，很多写法都能跑。  
如果数据规模是 10 万，`O(n^2)` 可能直接爆炸。

## 为什么不用秒数衡量算法

运行时间会受很多因素影响：

- 机器性能
- 编译器
- 输入数据
- 操作系统状态
- 语言本身

所以算法分析通常不直接说“跑几秒”，而是看随着输入规模 `n` 增大，操作次数怎么增长。

## 常见复杂度

从小到大大概是：

```text
O(1)
O(log n)
O(n)
O(n log n)
O(n^2)
O(n^3)
O(2^n)
O(n!)
```

几个直觉：

- `O(1)`：和输入规模无关。
- `O(log n)`：每次把规模缩小一半，比如二分。
- `O(n)`：扫一遍。
- `O(n log n)`：常见于高效排序。
- `O(n^2)`：两层循环。
- `O(2^n)`：枚举子集，经常只适合小规模。

## 最坏、平均、最好

同一个算法，不同输入可能表现不同。

比如快速排序：

- 平均 `O(n log n)`
- 最坏 `O(n^2)`

算法分析常看最坏情况，因为它给出上界保证。  
但实际工程里也会关心平均情况和常数。

## 大 O 不是精确时间

`O(n)` 不一定永远比 `O(n log n)` 快。  
数据规模小的时候，常数开销可能更重要。

比如一个复杂的 `O(n)` 算法，可能在小数据下比简单的 `O(n log n)` 还慢。

但随着 `n` 变大，复杂度的数量级通常会决定命运。

## 空间复杂度

除了时间，还要看额外空间。

比如归并排序时间是 `O(n log n)`，但需要额外数组，空间 `O(n)`。  
快速排序平均时间也是 `O(n log n)`，递归栈平均 `O(log n)`。

有时可以用空间换时间。  
比如哈希表把两数之和从 `O(n^2)` 降到 `O(n)`，代价是额外 `O(n)` 空间。

## 经典例题

分析：

```cpp
for (int i = 1; i <= n; i *= 2) {
    for (int j = 0; j < n; j++) {
        sum++;
    }
}
```

外层 `i` 每次乘 2，执行 `log n` 次。  
内层每次执行 `n` 次。

总复杂度：

```text
O(n log n)
```

再看：

```cpp
for (int i = 0; i < n; i++) {
    for (int j = i; j < n; j++) {
        sum++;
    }
}
```

执行次数：

```text
n + (n-1) + ... + 1 = n(n+1)/2
```

所以还是：

```text
O(n^2)
```

key：

- 复杂度看增长趋势，不看具体秒数。
- 最坏情况给算法上界。
- 时间和空间经常可以互相交换。
