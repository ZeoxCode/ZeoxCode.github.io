## 三级模式 两级映射

```
外模式（用户视图）       ← 不同用户看到的数据视图
    ↕  外模式/模式映射（保证逻辑独立性）
模式（概念模式/逻辑模式） ← 全体数据的逻辑结构
    ↕  模式/内模式映射（保证物理独立性）
内模式（存储模式）        ← 数据的物理存储方式
```

- **逻辑独立性**：模式改变，外模式不变（通过修改映射实现）
- **物理独立性**：内模式改变，模式不变（通过修改映射实现）

## 事务 ACID

- **A（原子性）**：事务中的操作要么全做，要么全不做
- **C（一致性）**：事务执行前后，数据库从一个一致状态到另一个一致状态
- **I（隔离性）**：并发事务之间互不干扰
- **D（持久性）**：事务一旦提交，结果永久保存

## 并发控制

**并发问题**：

| 问题 | 说明 |
|------|------|
| 脏读 | 读到了其他事务未提交的数据 |
| 不可重复读 | 同一事务中两次读同一数据，结果不同（被修改） |
| 幻读 | 同一事务中两次查询，行数不同（被插入/删除） |
| 丢失更新 | 两个事务同时修改同一数据，一个修改被覆盖 |

**隔离级别**（由低到高）：

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| READ UNCOMMITTED | ✓ | ✓ | ✓ |
| READ COMMITTED | ✗ | ✓ | ✓ |
| REPEATABLE READ | ✗ | ✗ | ✓ |
| SERIALIZABLE | ✗ | ✗ | ✗ |

**封锁协议**：
- **X锁（排他锁）**：读写都排他
- **S锁（共享锁）**：允许并发读，不允许写
- **两段锁协议（2PL）**：加锁阶段（不释放）→ 释放阶段（不加锁），可串行化但可能死锁

## 数据库恢复

**日志（Redo Log / Undo Log）**：
- Redo Log：记录已提交事务的修改，用于重做（崩溃恢复）
- Undo Log：记录事务修改前的值，用于回滚

**恢复策略**：
- **检查点（Checkpoint）**：定期将内存数据写盘，缩短恢复时间
- 崩溃恢复：从最近的检查点开始，重做已提交事务，撤销未提交事务

## 关系数据库设计

**函数依赖**：
- 完全函数依赖：X→Y，且X的任意真子集都不能决定Y
- 部分函数依赖：X→Y，但X的某个真子集也能决定Y
- 传递函数依赖：X→Y，Y→Z，则X传递决定Z

**范式**：

| 范式 | 要求 | 消除的问题 |
|------|------|-----------|
| 1NF | 属性不可再分（原子性） | - |
| 2NF | 1NF + 非主属性完全依赖于主键 | 消除部分依赖 |
| 3NF | 2NF + 非主属性不传递依赖于主键 | 消除传递依赖 |
| BCNF | 每个决定因素都包含候选键 | 消除主属性对主键的部分/传递依赖 |

## 分布式数据库

**CAP 定理**：分布式系统中，以下三个特性最多只能同时满足两个：
- **C（一致性）**：所有节点在同一时刻看到相同数据
- **A（可用性）**：每个请求都能收到响应（不保证最新数据）
- **P（分区容错性）**：网络分区时系统仍然运行

**BASE 理论**（CAP中选AP的权衡）：
- **BA**（Basically Available）：基本可用
- **S**（Soft State）：软状态，允许中间状态
- **E**（Eventually Consistent）：最终一致性

**数据分片策略**：
- 水平分片：按行划分（如按用户ID范围）
- 垂直分片：按列划分（不同属性存不同节点）
- 混合分片

## NoSQL 数据库

| 类型 | 代表 | 特点 | 适用场景 |
|------|------|------|---------|
| 键值存储 | Redis、Memcached | 极简，O(1)读写 | 缓存、Session |
| 文档数据库 | MongoDB、CouchDB | JSON文档，灵活 | 内容管理、用户数据 |
| 列族数据库 | HBase、Cassandra | 列式存储，适合大数据 | 时序数据、日志 |
| 图数据库 | Neo4j | 节点+边，关系查询快 | 社交网络、知识图谱 |

## 数据仓库

**OLTP vs OLAP**：

| 对比 | OLTP（联机事务处理） | OLAP（联机分析处理） |
|------|--------------------|--------------------|
| 目的 | 日常业务操作 | 决策支持、数据分析 |
| 数据量 | 较小（当前数据） | 海量（历史数据） |
| 操作 | 增删改查 | 复杂查询、聚合 |
| 响应时间 | 毫秒级 | 秒到分钟 |
| 数据库设计 | 高度规范化（3NF） | 反规范化（星型/雪花） |

**星型模式**：一张事实表 + 多张维度表，维度表不再细分
**雪花模式**：星型基础上，维度表继续规范化（查询复杂但存储小）

**ETL**：Extract（抽取）→ Transform（转换）→ Load（加载）
