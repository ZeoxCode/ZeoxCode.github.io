学排序时会发现，归并、快排、堆排都是 `O(n log n)`。  
那有没有可能更快？

答案要分情况。

## 比较排序的下界

如果排序只能通过比较两个元素大小来决定顺序，那么最坏情况下需要：

```text
Ω(n log n)
```

这叫比较排序下界。

常见比较排序：

- 冒泡排序
- 插入排序
- 选择排序
- 归并排序
- 快速排序
- 堆排序

其中归并、快排、堆排已经达到 `O(n log n)` 量级。

## 为什么有下界

排序的结果有 `n!` 种可能排列。  
每一次比较只有两种结果。

如果用决策树看，至少要有 `n!` 个叶子。  
二叉树高度至少是：

```text
log2(n!)
```

而：

```text
log(n!) = Ω(n log n)
```

所以比较排序不能突破 `n log n`。

## 线性排序怎么做到

线性排序不是靠比较，而是利用数据范围或数字结构。

典型算法：

- 计数排序
- 桶排序
- 基数排序

它们能在特定条件下达到 `O(n)` 或接近 `O(n)`。

## 计数排序

如果所有数都在 `0..k` 范围内，可以统计每个数出现次数。

```cpp
vector<int> cnt(k + 1);
for (int x : a) cnt[x]++;

vector<int> res;
for (int v = 0; v <= k; v++) {
    while (cnt[v]--) res.push_back(v);
}
```

复杂度：

```text
O(n + k)
```

如果 k 不大，很快。  
如果 k 特别大，空间会浪费。

## 基数排序

基数排序按位排序。

例如对整数先按个位排，再按十位排，再按百位排。  
关键是每一轮内部排序要稳定。

适合固定长度整数或字符串。

## 什么时候用线性排序

条件：

- 数据范围不大。
- 或者数据位数固定。
- 或者能合理分桶。

如果是任意对象比较，还是比较排序更通用。

key：

- 比较排序最坏下界是 `Ω(n log n)`。
- 线性排序能更快，是因为利用了额外条件。
- 计数排序适合范围小的整数。
