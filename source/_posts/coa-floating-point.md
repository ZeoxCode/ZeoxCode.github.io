很多语言里都有这个现象：

```text
0.1 + 0.2 != 0.3
```

不是语言坏了，而是浮点数表示本来就是近似的。

## 浮点数的基本思想

浮点数类似科学计数法：

```
1.234 × 10^5
```

二进制浮点数也是类似，只不过底数是 2。

IEEE 754 浮点数大致分成：

- 符号位
- 阶码
- 尾数

可以粗略理解为：

```
数值 = (-1)^符号 × 尾数 × 2^阶码
```

## 为什么 0.1 表示不精确

十进制的 `0.1` 在二进制里可能是无限循环小数。  
就像十进制里 `1/3 = 0.333333...` 一样。

计算机只能用有限位保存，所以只能截断或舍入。  
因此 `0.1` 存进去时，本身就已经不是精确的 0.1。

## 浮点数比较

所以浮点数不要直接用 `==` 比较。

更常见的做法是看误差是否足够小：

```c
if (fabs(a - b) < 1e-9) {
    // 认为相等
}
```

## 一个小结

浮点数适合表示很大或很小的近似值，但不适合做严格精确的小数计算。

key：

- 浮点数用科学计数法思想表示。
- 很多十进制小数无法被二进制有限表示。
- 浮点数比较要考虑误差。
