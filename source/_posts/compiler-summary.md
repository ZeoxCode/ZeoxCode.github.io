编译原理这一轮学下来，最重要的不是背各种分析表，而是看清楚代码被翻译的过程。

从源代码到机器执行，中间大概经过：

```text
字符流
  -> token
  -> 语法树
  -> 类型和作用域检查
  -> 中间代码
  -> 优化
  -> 目标代码
```

## 几个关键转换

### 字符到 token

词法分析负责切词。  
它不关心句子结构，只关心每个词是什么。

### token 到语法树

语法分析负责结构。  
表达式优先级、语句嵌套、函数定义，都在这里体现。

### 语法树到含义

语义分析检查类型、作用域、声明等问题。  
代码看起来合法，不代表含义正确。

### 中间代码到机器指令

IR 让编译器前后端分开。  
最后后端再根据目标机器生成指令。

## 和其他课的关系

编译原理和计组关系很近：  
目标代码最终要给 CPU 执行。

和操作系统也有关：  
函数调用栈、内存布局、链接加载，都会影响程序运行。

以后写代码看到报错，也可以反过来想：  
这是词法错、语法错、语义错，还是链接/运行时错误？

最后记一句：

> 编译器就是把人写的结构化文本，逐步翻译成机器能执行的指令，同时尽量检查错误、优化结果。
