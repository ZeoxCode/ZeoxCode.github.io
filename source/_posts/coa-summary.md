计组学完一轮，最重要的感觉是：程序终于从“代码”落到了“硬件动作”上。

以前看：

```c
a = b + c;
```

现在会想到：

- 数据在哪里？
- 是在寄存器还是内存？
- CPU 怎么取指？
- ALU 怎么运算？
- 结果写回哪里？

## 几条主线

### 1. 数据怎么表示

二进制只是位串。  
原码、补码、浮点数、字符编码，都是解释位串的方式。

这里最容易忘的是：  
同样的二进制，用不同规则解释，意义完全不同。

### 2. 指令怎么执行

CPU 反复做：

```
取指 -> 译码 -> 执行
```

PC 决定下一条指令。  
分支跳转会改变 PC。

### 3. 存储为什么分层

CPU 快，内存慢，磁盘更慢。  
所以有寄存器、Cache、主存、磁盘这一层层结构。

Cache 能工作，是因为程序有局部性。

### 4. 设备怎么和 CPU 配合

I/O 设备比 CPU 慢很多。  
中断让设备主动通知 CPU。  
DMA 让设备和内存直接搬数据，减少 CPU 负担。

## 和后面的关系

计组是操作系统的前置。

操作系统里讲进程切换，就要理解寄存器和现场保存。  
讲虚拟内存，就要理解地址和主存。  
讲 I/O，就要理解中断和 DMA。  
讲性能，就要理解 Cache 和流水线。

所以计组不是孤立的一门课，它是在给“程序如何真正运行”打底。

最后留一句：

> 程序运行 = 指令在 CPU 中执行 + 数据在存储层次中流动 + 设备通过总线、中断、DMA 协同工作。
