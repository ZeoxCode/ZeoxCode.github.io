## 加密算法分类

### 对称加密

加密和解密使用**同一密钥**，速度快，适合大量数据加密。

| 算法 | 密钥长度 | 块大小 | 特点 |
|------|---------|--------|------|
| DES | 56位 | 64位 | 已不安全 |
| 3DES | 112/168位 | 64位 | DES的改进版 |
| AES | 128/192/256位 | 128位 | 当前标准，推荐 |
| RC4 | 可变 | 流加密 | 用于SSL（已弃用） |

**问题**：密钥分发困难（如何安全地把密钥传给对方？）

### 非对称加密

使用**公钥加密，私钥解密**（或私钥签名，公钥验签），解决密钥分发问题，但速度慢。

| 算法 | 基础 | 用途 |
|------|------|------|
| RSA | 大整数分解难题 | 加密、数字签名 |
| DSA | 离散对数 | 仅数字签名 |
| ECC | 椭圆曲线离散对数 | 小密钥，移动设备 |
| DH | Diffie-Hellman密钥交换 | 安全协商会话密钥 |

### 哈希算法（摘要算法）

单向，不可逆，相同输入总是产生相同输出，用于验证数据完整性。

| 算法 | 输出长度 | 状态 |
|------|---------|------|
| MD5 | 128位 | 已不安全（碰撞攻击） |
| SHA-1 | 160位 | 已不安全 |
| SHA-256 | 256位 | 安全，推荐 |
| SHA-3 | 可变 | 最新标准 |

**实际使用**：对称加密传数据 + 非对称加密传对称密钥（混合加密），兼顾效率和安全。

## 数字签名

解决**认证**和**不可抵赖**问题。

```
发送方：
  1. 对消息取哈希 → 摘要
  2. 用发送方私钥加密摘要 → 数字签名
  3. 发送：消息 + 数字签名

接收方：
  1. 用发送方公钥解密签名 → 摘要A
  2. 对收到的消息取哈希 → 摘要B
  3. 比较摘要A == 摘要B → 验证通过
```

**注意**：数字签名是用**私钥加密**（不是公钥），验签是用**公钥解密**。

## 数字证书与 PKI

**数字证书**：由 CA（证书颁发机构）签发，绑定公钥和身份信息。
- 包含：主体信息、公钥、有效期、CA签名
- 格式：X.509

**PKI（公钥基础设施）**：
- CA：签发和管理证书
- RA：注册机构，负责审核
- CRL：证书吊销列表
- OCSP：在线证书状态协议（实时查询）

**信任链**：终端证书 → 中间CA证书 → 根CA证书（预置在操作系统/浏览器中）

## SSL/TLS

- SSL 3.0 → TLS 1.0 → TLS 1.1 → TLS 1.2（主流）→ TLS 1.3（最新）
- TLS 1.3 移除了不安全的加密套件，握手只需 1-RTT

**TLS 握手（TLS 1.2）**：
```
1. Client Hello（支持的协议、加密套件、随机数）
2. Server Hello（选定的套件、证书、随机数）
3. Client 验证证书
4. Client 发送 Pre-Master Secret（用服务器公钥加密）
5. 双方用三个随机数生成会话密钥
6. 后续使用对称加密通信
```

## 防火墙

| 类型 | 工作层次 | 特点 |
|------|---------|------|
| 包过滤防火墙 | 网络层 | 基于IP/端口过滤，速度快，无状态 |
| 状态检测防火墙 | 传输层 | 跟踪连接状态，安全性更高 |
| 应用代理防火墙 | 应用层 | 深度检查应用内容，速度慢但最安全 |
| WAF（Web应用防火墙） | 应用层 | 专门针对Web攻击 |

**DMZ（非军事区）**：
```
Internet → 外部防火墙 → DMZ（Web服务器、邮件服务器）→ 内部防火墙 → 内网
```
DMZ 中的服务器可以被外部访问，但被隔离在内网之外。

## 入侵检测与防御

- **IDS（入侵检测系统）**：只检测，不阻断，报警
- **IPS（入侵防御系统）**：检测并主动阻断
- 检测方法：
  - **异常检测**：建立基线，检测偏差（误报率高）
  - **误用检测（特征检测）**：匹配已知攻击特征（漏报新攻击）

## 常见攻击与防御

| 攻击 | 原理 | 防御 |
|------|------|------|
| SQL 注入 | 拼接恶意SQL语句 | 参数化查询、ORM |
| XSS（跨站脚本） | 注入恶意脚本到网页 | 输出编码、CSP |
| CSRF（跨站请求伪造） | 利用已登录状态发请求 | CSRF Token、SameSite Cookie |
| DDoS | 大量请求耗尽资源 | 流量清洗、CDN、限速 |
| 中间人攻击 | 拦截并篡改通信 | HTTPS、证书固定 |
| 暴力破解 | 枚举密码 | 账号锁定、验证码、MFA |
| 社会工程学 | 欺骗人获取信息 | 安全意识培训 |

## 安全等级保护（等保）

等保 2.0 分五个级别：
- **一级**：自主保护（用户自行保护）
- **二级**：指导保护（有限监管）
- **三级**：监督保护（国家重点监管，最常见的合规目标）
- **四级**：强制保护（关键基础设施）
- **五级**：专控保护（国家机密，最高级）

**考点**：等保三级是大多数互联网企业、政府系统的要求。
