前面学了很多零散协议。
最好的复习方式，是把它们串成一次完整的网页访问。

假设在浏览器输入：

```
https://www.example.com/index.html
```

## 第一步：DNS 解析

浏览器不能直接用域名发 IP 包。
所以先要通过 DNS 找到 `www.example.com` 对应的 IP 地址。

如果本地有缓存，直接用缓存。
如果没有，就向 DNS 服务器查询。

结果可能是：

```
www.example.com -> 93.184.216.34
```

## 第二步：判断是否同网段

主机拿到目标 IP 后，会判断目标是否和自己在同一个网段。

如果同网段，可以直接 ARP 目标主机 MAC。
如果不同网段，就把数据交给默认网关。

访问公网网站通常不同网段，所以第一跳发给路由器。

## 第三步：建立 TCP 连接

HTTPS 默认使用 TCP 443 端口。
浏览器会和服务器建立 TCP 连接。

这个过程就是三次握手：

```
SYN -> SYN+ACK -> ACK
```

连接建立后，双方才开始传输应用层数据。

## 第四步：TLS 握手

因为是 HTTPS，所以 TCP 连接建立后，还要进行 TLS 握手。

这一步主要完成：

- 验证服务器证书
- 协商加密算法
- 协商对称密钥

之后 HTTP 数据会被加密传输。

## 第五步：发送 HTTP 请求

浏览器发送类似这样的请求：

```http
GET /index.html HTTP/1.1
Host: www.example.com
```

服务器处理请求后返回响应：

```http
HTTP/1.1 200 OK
Content-Type: text/html

...
```

## 第六步：逐层封装与转发

HTTP 数据往下走：

```
HTTP -> TCP -> IP -> Ethernet
```

每一层都加自己的头部。

中间路由器主要看 IP 头，决定下一跳。
每经过一跳，链路层的 MAC 地址会变化，但目标 IP 仍然指向最终服务器。

## 经典例题

**问题：访问 HTTPS 网站时，DNS、TCP、TLS、HTTP 的顺序是什么？**

顺序是：

```
DNS -> TCP 三次握手 -> TLS 握手 -> HTTP 请求响应
```

DNS 先把域名变成 IP。
TCP 先建立可靠连接。
TLS 再建立安全通道。
HTTP 最后在安全通道里传输请求和响应。

## 不能忘的点

- 一次网页请求会经过多个协议，不是 HTTP 单独完成。
- DNS 找 IP，TCP 建连接，TLS 保安全，HTTP 传内容。
- 数据传输时会逐层封装，经过路由器逐跳转发。
