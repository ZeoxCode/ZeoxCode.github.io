语法正确，不代表程序有意义。

比如：

```c
int x;
x = "hello";
```

语法上像一条赋值语句，但类型不匹配。

语义分析要检查这些更深的规则。

## 语义分析做什么

常见工作：

- 类型检查
- 变量是否声明
- 函数参数个数是否匹配
- 返回值类型是否正确
- 作用域检查

比如：

```c
int f(int a) {
    return "abc";
}
```

语法结构没问题，但函数声明返回 `int`，实际返回字符串，语义错误。

## 符号表

语义分析需要记录标识符信息，这就要用符号表。

符号表里可能保存：

- 变量名
- 类型
- 作用域
- 地址偏移
- 是否为函数
- 参数列表

当编译器看到一个变量名时，就去符号表里查它有没有声明、类型是什么。

## 作用域

例子：

```c
int x = 1;
{
    int x = 2;
}
```

内部作用域的 `x` 会遮蔽外部的 `x`。  
所以符号表通常要支持作用域嵌套。

key：

- 语法分析看结构，语义分析看含义。
- 类型检查和作用域检查是语义分析重点。
- 符号表是语义分析的重要数据结构。
