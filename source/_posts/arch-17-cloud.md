## 云计算基本概念

**NIST 定义的五个特征**：
- 按需自助服务
- 无处不在的网络访问
- 资源池化（多租户）
- 快速弹性伸缩
- 可计量服务（按用量计费）

## 服务模型

| 模型 | 全称 | 提供商管理 | 用户管理 | 举例 |
|------|------|----------|---------|------|
| **IaaS** | 基础设施即服务 | 物理机、网络、虚拟化 | OS、运行时、应用、数据 | AWS EC2、阿里云ECS |
| **PaaS** | 平台即服务 | IaaS + OS + 运行时 | 应用、数据 | Heroku、Google App Engine |
| **SaaS** | 软件即服务 | 全部 | 无（只是使用） | Gmail、Salesforce、钉钉 |

**记忆**：Pizza as a Service（外卖/餐厅/食材类比）
- 自己做饭 = 自建机房
- 买食材 = IaaS（买原料自己做）
- 外卖 = SaaS（直接吃）

**部署模型**：
- **公有云**：资源由云服务商管理，多租户共享（AWS、Azure、阿里云）
- **私有云**：资源专属某一组织（OpenStack）
- **混合云**：公有云+私有云，数据/应用在两者间流动
- **社区云**：特定行业/组织共享（政务云、金融云）

## 虚拟化技术

**类型一（裸金属虚拟化）**：Hypervisor 直接运行在硬件上（VMware ESXi、Hyper-V、KVM）
**类型二（宿主机虚拟化）**：Hypervisor 运行在操作系统上（VirtualBox、VMware Workstation）

**虚拟化层次**：
- 硬件虚拟化：CPU/内存/IO虚拟化
- 操作系统虚拟化：容器（共享OS内核，更轻量）

## Docker 容器

```
应用代码 + 依赖 + 配置 → Docker镜像（Image）→ 运行 → 容器（Container）
```

**核心概念**：
- **镜像（Image）**：只读模板，通过 Dockerfile 构建
- **容器（Container）**：镜像的运行实例，可启停、删除
- **仓库（Registry）**：存储镜像（Docker Hub、私有仓库）
- **Dockerfile**：定义如何构建镜像的脚本

**容器 vs 虚拟机**：

| 对比 | 虚拟机 | 容器 |
|------|--------|------|
| 隔离级别 | 强（独立OS） | 较弱（共享内核） |
| 启动时间 | 分钟级 | 秒级 |
| 大小 | GB级 | MB级 |
| 密度 | 低（一台机器几十个VM） | 高（一台机器几百个容器） |
| 适用 | 强隔离、不同OS | 微服务、CI/CD |

## Kubernetes（K8s）

**容器编排平台**，管理大规模容器集群。

**核心概念**：
- **Pod**：最小调度单元，包含一或多个容器，共享网络和存储
- **Node**：运行Pod的机器（物理机或虚拟机）
- **Cluster**：Node的集合
- **Deployment**：声明式管理Pod副本数（自动扩缩容、滚动更新）
- **Service**：为Pod提供稳定的网络访问地址（负载均衡）
- **Ingress**：集群外部访问的入口（类似API网关）
- **ConfigMap / Secret**：配置和敏感信息管理
- **Namespace**：资源隔离（多团队/多环境）

**控制平面组件**：
- **API Server**：集群的入口，接收所有管理操作
- **etcd**：集群状态存储（键值数据库）
- **Scheduler**：决定Pod调度到哪个Node
- **Controller Manager**：确保实际状态与期望状态一致

## 云原生

**CNCF 定义的云原生四要素**：
- **容器化**：应用打包为容器
- **微服务**：服务拆分
- **动态管理**：通过编排平台（K8s）自动管理
- **DevOps**：开发与运维协作

## DevOps

**理念**：打破开发（Dev）和运维（Ops）的壁垒，实现快速交付。

```
代码提交 → CI（持续集成）→ CD（持续交付/部署）→ 生产环境
    ↑                                              ↓
  反馈 ←←←←←←←←← 监控告警 ←←←←←←←←←←←←←←←←←←←←←←
```

**CI（持续集成）**：代码提交后自动构建、测试，快速发现集成问题
**CD（持续交付）**：代码随时可以部署到生产，手动触发
**CD（持续部署）**：代码通过测试后自动部署到生产，无需人工干预

**典型工具链**：
- 代码：Git（GitHub/GitLab）
- CI/CD：Jenkins、GitHub Actions、GitLab CI
- 容器：Docker
- 编排：Kubernetes
- 监控：Prometheus + Grafana
- 日志：ELK Stack

## 弹性伸缩

- **水平扩展（Scale Out）**：增加实例数量，分担负载（更常用）
- **垂直扩展（Scale Up）**：增加单台机器的CPU/内存（有上限）
- **自动扩缩容（Auto Scaling）**：根据负载指标自动增减实例
