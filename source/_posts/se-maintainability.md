代码能跑只是第一步。  
能不能让以后的人看懂、修改、扩展，也很重要。

可维护性差的代码，短期看像省时间，长期看会还债。

## 什么代码难维护

常见问题：

- 函数太长
- 命名不清楚
- 重复代码太多
- 逻辑嵌套太深
- 注释和代码不一致
- 一个模块做太多事

这些问题单独看都不致命，但堆起来就会让项目越来越难改。

## 命名很重要

比如：

```java
int d;
```

不如：

```java
int daysUntilDeadline;
```

好的命名能减少解释成本。

## 注释不是越多越好

注释应该解释“为什么”，而不是重复“做什么”。

不好：

```java
i++; // i 加 1
```

较好：

```java
// 跳过表头行，从第一条数据开始统计
```

key：

- 可维护性决定代码长期价值。
- 命名、拆分、去重复都很重要。
- 注释要解释原因和背景，不要重复代码本身。
