中断这个概念很重要，因为它把硬件和操作系统连起来了。

如果没有中断，CPU 想知道键盘有没有输入，可能要一直问：

```
有输入吗？
有输入吗？
有输入吗？
```

这叫轮询，很浪费。

中断的思想是：

> 设备有事时主动通知 CPU。

## 中断大概过程

以键盘输入为例：

1. 用户按下键。
2. 键盘控制器发出中断请求。
3. CPU 暂停当前程序。
4. CPU 保存现场。
5. 跳转到中断服务程序。
6. 处理完后恢复现场，继续执行原程序。

## 保存现场为什么重要

CPU 被打断时，原程序可能正在执行到一半。  
如果不保存寄存器、PC 等状态，回来后就不知道原来执行到哪里了。

所以中断不是简单跳走，而是要保存和恢复上下文。

## 中断和异常

粗略理解：

- 中断：外部设备引起，比如键盘、磁盘、网卡。
- 异常：CPU 执行指令时内部产生，比如除零、缺页、非法指令。

操作系统里的系统调用、缺页异常、时钟中断，都和这个机制有关。

key：

- 中断让 CPU 不必一直轮询设备。
- 中断处理前要保存现场，处理后要恢复现场。
- 中断是理解操作系统调度和 I/O 的前置概念。
