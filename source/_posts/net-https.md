HTTP 本身是明文的。
如果在公共 Wi-Fi 下直接用 HTTP 登录网站，别人可能看到账号密码。

HTTPS 解决的问题是：

> 让 HTTP 通信变得安全。

## HTTPS 多了什么

HTTPS 可以简单理解为：

```
HTTPS = HTTP + TLS
```

TLS 提供三件事：

- 加密：别人看不到内容。
- 身份认证：确认服务器是真的。
- 完整性校验：防止内容被篡改。

## 为什么需要证书

如果浏览器访问银行网站，它要确认对方真的是银行，而不是伪造网站。

证书就是用来证明服务器身份的。
证书由 CA 机构签发，浏览器内置了一些可信 CA。

如果服务器给出的证书不可信，浏览器就会报警。

## 对称加密和非对称加密

HTTPS 同时用到了两种加密思想。

对称加密：

- 加密和解密用同一把钥匙。
- 速度快。
- 问题是密钥怎么安全传给对方。

非对称加密：

- 有公钥和私钥。
- 公钥可以公开，私钥自己保存。
- 适合用来协商密钥，但速度较慢。

所以 HTTPS 通常是：
先用非对称加密和证书完成身份认证、协商密钥，再用对称加密传输数据。

## 经典例题

**问题：HTTPS 为什么不全程只用非对称加密？**

因为非对称加密计算开销大，速度慢。
实际传输网页、图片、视频时数据量很大，如果全程都用非对称加密，效率会很差。

所以更合理的做法是：
用非对称加密安全地协商出对称密钥，然后用对称加密传输大量数据。

## 不能忘的点

- HTTPS = HTTP + TLS。
- 证书用来证明服务器身份。
- 非对称加密用于认证和协商密钥，对称加密用于大量数据传输。
