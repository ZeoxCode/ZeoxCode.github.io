编译的后端要把中间代码变成目标机器代码。

这里终于和计组接上了：  
目标代码最终要变成 CPU 能执行的指令。

## 从三地址码到指令

中间代码：

```text
t1 = b * c
t2 = a + t1
x = t2
```

可能生成类似：

```asm
LOAD R1, b
LOAD R2, c
MUL  R3, R1, R2
LOAD R4, a
ADD  R5, R4, R3
STORE x, R5
```

真实机器会更复杂，但思路就是把中间运算映射到机器指令。

## 寄存器分配

CPU 寄存器数量有限。  
中间代码里的临时变量可能很多，不可能都放进寄存器。

编译器要决定：

- 哪些变量放寄存器
- 哪些变量放内存
- 寄存器不够时怎么溢出到栈上

这叫寄存器分配。

## 指令选择

同一个操作可能有不同指令实现。  
编译器要选择合适的机器指令。

比如某些机器有乘加指令，可以把乘法和加法合成一条更高效的指令。

key：

- 代码生成把 IR 变成机器相关指令。
- 寄存器分配很重要，因为寄存器很少但很快。
- 后端优化和具体 CPU 架构关系很大。
