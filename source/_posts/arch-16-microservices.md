## 单体 vs SOA vs 微服务

| 对比 | 单体架构 | SOA | 微服务 |
|------|---------|-----|--------|
| 粒度 | 整体 | 粗粒度服务 | 细粒度服务 |
| 部署 | 整体部署 | 分服务部署 | 独立部署 |
| 通信 | 进程内调用 | ESB/SOAP | HTTP/gRPC/消息队列 |
| 数据库 | 共享 | 可共享 | 每个服务独立DB |
| 扩展 | 整体扩展 | 按服务扩展 | 按服务独立扩展 |
| 适合 | 小型项目 | 企业集成 | 大型互联网 |

## 微服务拆分原则

- **单一职责**：每个服务只做一件事
- **高内聚低耦合**：服务内部高度相关，服务之间最小依赖
- **领域驱动设计（DDD）**：按业务领域（Bounded Context）拆分
- **数据隔离**：每个服务拥有自己的数据库，不直接访问其他服务的数据
- **粒度适中**：不要拆得太细（管理复杂），也不要太粗（失去微服务价值）

## 核心组件

### API 网关

```
客户端 → API Gateway → 微服务A
                    ↘ 微服务B
                    ↘ 微服务C
```

**功能**：
- 路由转发
- 认证授权（统一鉴权，服务不用各自实现）
- 限流熔断
- 协议转换（HTTPS→HTTP）
- 日志聚合
- 负载均衡

**典型产品**：Kong、Nginx、Spring Cloud Gateway、Zuul

### 服务注册与发现

```
服务启动 → 注册到 Registry（如Eureka/Consul/Zookeeper）
服务调用 → 从 Registry 查找目标服务地址 → 调用
```

- **客户端发现**：客户端查询注册中心，自己选择实例（如 Ribbon）
- **服务端发现**：客户端请求负载均衡器，由它查注册中心并转发

### 负载均衡

- **轮询（Round Robin）**：依次分配
- **加权轮询**：按权重分配（性能好的服务器权重高）
- **最少连接**：分配给连接数最少的服务器
- **IP Hash**：同一IP固定到同一服务器（Session粘滞）
- **随机**：随机分配

### 熔断器（Circuit Breaker）

防止级联故障（一个服务崩溃导致整个系统雪崩）。

```
状态机：
CLOSED（正常）→ OPEN（熔断，快速失败）→ HALF-OPEN（探测恢复）→ CLOSED
         失败率过高↑              定时↑           成功↑
```

- **CLOSED**：正常调用，统计失败率
- **OPEN**：熔断，直接返回错误（快速失败），不调用下游
- **HALF-OPEN**：允许少量请求通过，探测下游是否恢复

**典型产品**：Netflix Hystrix、Resilience4j

## 分布式事务

微服务每个服务有独立DB，跨服务操作需要分布式事务。

### 2PC（两阶段提交）

```
阶段1（Prepare）：协调者问所有参与者"能提交吗？"
阶段2（Commit/Rollback）：都同意则提交，有一个拒绝则回滚
```

- 优点：强一致性
- 缺点：同步阻塞，协调者单点故障，不适合高并发

### Saga 模式

- 将长事务拆分为一系列本地事务，每步完成后发布事件触发下一步
- 补偿事务（Compensating Transaction）：如果某步失败，执行反向操作回滚
- **编排式（Choreography）**：服务间通过事件驱动，无中心协调
- **指挥式（Orchestration）**：中央协调器（Saga Orchestrator）控制流程

### TCC（Try-Confirm-Cancel）

- **Try**：预留资源（冻结库存）
- **Confirm**：确认提交（扣减库存）
- **Cancel**：释放资源（解冻库存）

## 服务间通信

| 方式 | 同步/异步 | 代表 | 适用场景 |
|------|---------|------|---------|
| HTTP/REST | 同步 | Spring Cloud Feign | 实时查询 |
| gRPC | 同步 | Protocol Buffers | 高性能内部服务 |
| 消息队列 | 异步 | Kafka、RabbitMQ | 解耦、削峰填谷 |
| GraphQL | 同步 | Apollo | 灵活查询 |

## 配置中心

- 集中管理所有服务的配置，修改后实时推送到服务
- **典型产品**：Spring Cloud Config、Nacos、Apollo
- 好处：不用重启服务就能改配置，支持配置回滚

## 可观测性（Observability）

微服务系统复杂，需要三大支柱：
- **日志（Logs）**：结构化日志，集中收集（ELK：Elasticsearch+Logstash+Kibana）
- **指标（Metrics）**：CPU、内存、QPS、错误率（Prometheus + Grafana）
- **链路追踪（Tracing）**：追踪一次请求经过哪些服务（Zipkin、Jaeger、SkyWalking）
