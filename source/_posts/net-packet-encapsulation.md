理解网络分层之后，下一步要理解：数据在各层之间是怎么传递的。

核心概念叫**封装**。

## 什么是封装

应用程序产生的数据，不能直接丢到网线上。
每一层协议都要加上自己需要的信息，这些信息通常叫“头部”。

以访问网页为例：

```
HTTP 数据
↓ 加 TCP 头
TCP 段
↓ 加 IP 头
IP 数据报
↓ 加以太网头和尾
以太网帧
```

发送方是从上往下封装。
接收方是从下往上拆封。

## 每层加的头有什么用

假设浏览器向服务器发送一句：

```
GET /index.html
```

这句话本身只是应用层数据。
TCP 要知道这是从哪个端口发到哪个端口，所以会加端口号。
IP 要知道从哪台主机发到哪台主机，所以会加源 IP 和目的 IP。
以太网要知道这一跳发给谁，所以会加源 MAC 和目的 MAC。

可以粗略理解成：

| 层次 | 加的信息 | 作用 |
|---|---|---|
| TCP | 端口、序号、确认号 | 找进程、保证可靠 |
| IP | 源 IP、目的 IP | 找主机 |
| Ethernet | 源 MAC、目的 MAC | 找下一跳设备 |

## 类比寄快递

数据本身像快递里的物品。
TCP 头像写着“交给哪个房间的人”。
IP 头像写着“交给哪个城市哪栋楼”。
以太网头像写着“下一站先送到哪个中转站”。

每经过一跳，链路层头部可能会变化；但 IP 层的目标地址通常还是最终目的地。

## 经典例题

**问题：一台主机向外网服务器发送数据时，目的 IP 和目的 MAC 分别是谁？**

答案：

- 目的 IP：外网服务器的 IP。
- 目的 MAC：默认网关，也就是路由器的 MAC。

解释：
IP 层关心最终目标，所以目的 IP 是服务器。
链路层只关心当前这一跳，所以目的 MAC 是本地路由器。

## 不能忘的点

- 发送数据是逐层封装，接收数据是逐层拆封。
- TCP 头解决进程和可靠性，IP 头解决主机，MAC 头解决下一跳。
- 目的 IP 通常指最终目标，目的 MAC 通常只指下一跳。
