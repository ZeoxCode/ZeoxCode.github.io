刚开始看计算机网络，最容易被各种名词吓住：HTTP、TCP、IP、MAC、路由、交换机、DNS。
这些东西如果混在一起学，会觉得每个都像重点，但又不知道它们之间是什么关系。

所以第一件事不是背协议，而是理解**网络为什么要分层**。

## 为什么要分层

假设我要在浏览器里访问一个网页：

```
https://example.com
```

这里至少有几个问题：

- 浏览器要用什么格式和服务器交流？
- 数据太大时怎么拆开传？
- 服务器 IP 地址怎么找？
- 数据到了本机后交给哪个程序？
- 这一跳到底发给哪台设备？

如果一个协议同时解决所有问题，它会非常复杂，也很难修改。
分层的好处就是：**每一层只管自己的事，上层不用知道下层细节。**

## TCP/IP 四层模型

实际学习中，最常用的是 TCP/IP 四层模型：

| 层次 | 解决的问题 | 常见协议 |
|---|---|---|
| 应用层 | 应用程序之间说什么、怎么说 | HTTP、DNS、FTP |
| 传输层 | 数据交给哪一个进程，是否可靠 | TCP、UDP |
| 网络层 | 数据从哪台主机到哪台主机 | IP、ICMP |
| 链路层 | 当前这一跳怎么传 | Ethernet、ARP |

可以用一句话记：

> 应用层关心内容，传输层关心进程，网络层关心主机，链路层关心下一跳。

## 一个具体例子

浏览器访问网页时，大概是这样：

1. HTTP 生成请求：我要 `/index.html`。
2. TCP 把请求数据分成段，并保证可靠传输。
3. IP 负责把数据送到目标服务器的 IP 地址。
4. 以太网负责把数据先送到当前局域网里的下一跳，比如路由器。

每往下一层，就会多加一些控制信息；每往上一层，就会拆掉一层控制信息。

## 经典问题

**问题：为什么有了 IP 地址，还需要 MAC 地址？**

因为它们解决的问题不同。

IP 地址负责全局定位，告诉我们目标主机大概在哪个网络。
MAC 地址负责局域网内的一跳投递，告诉网卡这一帧要交给当前链路上的哪台设备。

比如从家里访问百度，目标 IP 是百度服务器，但第一跳的 MAC 地址通常不是百度，而是家里路由器的 MAC 地址。

## 不能忘的点

- 分层是为了降低复杂度，每层只解决自己的问题。
- TCP/IP 四层模型比 OSI 七层更常用。
- 网络通信不是“一步到终点”，而是每一层配合、每一跳转发。
