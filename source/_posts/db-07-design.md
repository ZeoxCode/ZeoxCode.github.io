## 设计阶段

```
需求分析 → 概念设计（ER图）→ 逻辑设计（关系模式）→ 物理设计 → 实施 → 运维
```

## ER图要素

- **实体**：矩形框，如 学生、课程
- **属性**：椭圆，连线到实体
- **联系**：菱形框，表示实体间的关系
- **主键属性**：下划线标注

## 联系类型

```
1:1  一对一  一个班级只有一个班长
1:N  一对多  一个学生选多门课（学生角度）
M:N  多对多  学生和课程之间
```

## ER图转关系模式

### 1:N 联系

```
将 "1" 端的主键加入 "N" 端的关系中作为外键

系(Dno, Dname)
学生(Sno, Sname, Dno)  ← Dno 是外键
```

### M:N 联系

```
联系本身单独建一张表，包含两端的主键

学生(Sno, Sname)
课程(Cno, Cname)
选课(Sno, Cno, Grade)  ← 联系表，主键为(Sno, Cno)
```

### 1:1 联系

```
将任意一端的主键加入另一端即可
一般加到查询频率高的那端
```

## 常见坑

- M:N 联系**必须**单独建表，不能把一端主键加入另一端（会产生多值）
- 联系本身可以有属性，如"选课"联系有"成绩"属性，成绩要放联系表里
- 弱实体（没有独立主键，依赖强实体）用双矩形表示
