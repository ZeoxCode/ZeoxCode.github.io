HTTP 是浏览网页时最常见的应用层协议。

它解决的问题是：

> 浏览器和服务器之间，用什么格式请求和返回资源。

## HTTP 是请求-响应模型

浏览器先发请求，服务器再返回响应。

一个简单请求像这样：

```http
GET /index.html HTTP/1.1
Host: example.com
```

服务器响应可能像这样：

```http
HTTP/1.1 200 OK
Content-Type: text/html

<html>...</html>
```

所以 HTTP 的核心就是：请求行、请求头、请求体，响应行、响应头、响应体。

## HTTP 方法

常见方法：

| 方法 | 含义 |
|---|---|
| GET | 获取资源 |
| POST | 提交数据 |
| PUT | 更新资源 |
| DELETE | 删除资源 |

GET 通常用于读，POST 常用于提交表单或创建数据。
不过具体语义也要看服务端怎么设计。

## HTTP 状态码

状态码告诉客户端请求结果。

常见分类：

- 2xx：成功
- 3xx：重定向
- 4xx：客户端错误
- 5xx：服务端错误

常见例子：

- 200：成功
- 301/302：重定向
- 404：资源不存在
- 500：服务器内部错误

## HTTP 无状态是什么意思

HTTP 本身不记得上一次请求。
每个请求从协议角度看都是独立的。

但网站需要登录状态怎么办？
通常用 Cookie、Session、Token 等机制在应用层维护状态。

## 经典例题

**问题：HTTP 是无状态的，为什么网站还能记住我已经登录？**

因为登录状态不是 HTTP 协议本身记住的。
服务器会给浏览器一个 Cookie 或 Token，浏览器以后每次请求都带上它，服务器再根据这个信息识别用户。

## 不能忘的点

- HTTP 是应用层的请求-响应协议。
- 状态码表示请求结果。
- HTTP 本身无状态，登录状态要靠 Cookie、Session、Token 等机制补充。
