## 事务

一组操作，要么全部成功，要么全部失败。

```sql
BEGIN TRANSACTION;
    UPDATE Account SET balance = balance - 100 WHERE id = 1;
    UPDATE Account SET balance = balance + 100 WHERE id = 2;
COMMIT;      -- 全部成功则提交
-- ROLLBACK; -- 任一失败则回滚
```

## ACID 特性

| 特性 | 含义 |
|------|------|
| 原子性 Atomicity | 事务中的操作要么全做，要么全不做 |
| 一致性 Consistency | 事务执行前后数据库处于合法状态 |
| 隔离性 Isolation | 并发事务互不干扰 |
| 持久性 Durability | 提交后的修改永久保存 |

## 并发问题

```
丢失修改：T1和T2同时读值100，T1改为90，T2改为120，T1修改被覆盖丢失
不可重复读：T1两次读同一数据，T2在中间修改了该数据，T1两次读结果不同
脏读：T1读到了T2未提交的数据，T2随后回滚，T1读到的是脏数据
幻读：T1两次查询，T2在中间插入新行，T1第二次多了几行
```

## 封锁协议

```
共享锁（S锁）：读锁，允许其他事务加S锁，不允许加X锁
排他锁（X锁）：写锁，不允许其他事务加任何锁

一级封锁协议：写前加X锁，事务结束释放 → 防止丢失修改
二级封锁协议：一级 + 读前加S锁，读完释放 → 防止脏读
三级封锁协议：一级 + 读前加S锁，事务结束释放 → 防止不可重复读
```

## 死锁

```
T1 持有A的锁，等待B
T2 持有B的锁，等待A
→ 死锁

预防：一次性申请所有锁，或按顺序申请
检测：等待图中出现环路
解除：选择代价最小的事务回滚
```

## 常见坑

- S锁和S锁**相容**，S锁和X锁、X锁和X锁**不相容**
- 两段锁协议（2PL）可以保证可串行化，但不能防止死锁
- 隔离级别越高，并发度越低，性能越差
