## 案例分析题型概述

案例分析共 25 分，一般 2~3 道题，每题 12~15 分。
考察形式：给出一段系统描述，然后提几个问题。

**常见题型**：
- 架构风格/模式识别
- 质量属性分析（ATAM）
- 设计模式应用
- 数据库设计
- 系统扩展性/可用性设计
- UML 图填写/补全

---

## 架构风格题答题模板

**题目形式**：该系统采用了哪种架构风格？有什么优缺点？

**答题步骤**：
1. 说出架构风格名称
2. 解释该风格的定义（1~2句）
3. 结合题目描述说优点（联系题目场景）
4. 说缺点

**例**：
> 系统将音视频数据经过编解码模块、水印模块、压缩模块依次处理后输出。

答：该系统采用了**管道-过滤器**架构风格。该风格将系统分解为一系列过滤器和连接它们的管道，数据流经各过滤器被逐步处理。
- 优点：各过滤器独立，可重用；支持并发流水线处理；易于添加新的处理步骤
- 缺点：不适合需要共享数据的场景；不适合交互式系统

## 质量属性题答题模板

**题目形式**：系统需要满足哪些质量属性？请列举相关战术。

**高频质量属性与战术速查**：

**性能**：
- 使用缓存（Redis）减少数据库压力
- 异步处理（消息队列）提高吞吐量
- CDN 加速静态资源
- 数据库读写分离、分库分表

**可用性**：
- 主备切换（热备/冷备）
- 负载均衡（去除单点故障）
- 熔断降级（Hystrix）
- 健康检查 + 自动重启

**可修改性**：
- 接口与实现分离（面向接口编程）
- 配置外部化（配置中心）
- 插件化架构（微内核）
- 使用设计模式封装变化点

**安全性**：
- 认证授权（JWT、OAuth）
- 输入验证（防SQL注入、XSS）
- 传输加密（HTTPS/TLS）
- 审计日志

## 设计模式题答题模板

**题目形式**：请说明此处使用了哪种设计模式，并画出类图/说明结构。

**识别关键词速查表**：

| 关键描述 | 模式 |
|---------|------|
| 一个接口，多种实现，运行时切换 | 策略模式 |
| 对象状态变化时通知其他对象 | 观察者模式 |
| 为其他对象提供代理/占位符 | 代理模式 |
| 动态添加功能，比继承灵活 | 装饰器模式 |
| 接口不兼容，需要转换 | 适配器模式 |
| 只能有一个实例，全局访问 | 单例模式 |
| 树形结构，统一对待叶节点和容器 | 组合模式 |
| 算法骨架固定，某些步骤由子类实现 | 模板方法 |
| 将请求沿链传递，直到被处理 | 责任链模式 |
| 分离抽象和实现，两者独立变化 | 桥接模式 |
| 创建一系列相关产品，保证兼容 | 抽象工厂 |
| 子类决定实例化哪个类 | 工厂方法 |
| 将请求封装为对象，支持撤销 | 命令模式 |

## 数据库设计题答题模板

**范式判断答题步骤**：
1. 找出所有函数依赖
2. 判断是否满足 2NF（有无非主属性对主键的部分依赖）
3. 判断是否满足 3NF（有无传递依赖）
4. 如不满足，说明哪张表有问题，如何分解

**分布式数据库题**：
- CAP 三选二，系统选了哪两个，为什么放弃第三个
- 最终一致性适用场景

## 高频考点汇总

**必考知识点**（每次考试基本都有）：
- 设计模式（创建型+结构型+行为型，认识23种的意图和结构）
- 架构风格（管道-过滤器、分层、事件驱动、微内核、黑板）
- ATAM（敏感点、权衡点、风险点）
- UML（用例图include/extend、类图六种关系、序列图）

**高频考点**（3年内出现过）：
- 微服务vs单体vs SOA对比
- REST vs SOAP
- 分布式事务（2PC、Saga、TCC）
- 数据库事务隔离级别
- 负载均衡算法
- 安全（加密算法、数字签名、防火墙类型）

## 答题技巧

1. **先读题，再看材料**：知道问什么，带着问题读，效率更高
2. **关键词定模式**：题目描述中的关键词往往直接对应某个模式或风格
3. **分点作答**：每个要点单独成行，条理清晰，阅卷老师看得清楚
4. **结合题目**：不要只写教科书定义，要结合题目场景说明
5. **字迹工整**：手写题中字迹清晰比内容更重要
6. **时间分配**：案例分析 75 分钟，每题不超过 25 分钟，先做熟悉的
