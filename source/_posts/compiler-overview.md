学完一点计组之后，再看编译原理会顺很多。

计组回答的是：CPU 怎么执行指令。  
编译原理回答的是：高级语言代码怎么变成这些指令。

一段 C 代码：

```c
int x = a + b * 3;
```

机器不会直接理解它。编译器要一步步把它翻译成更底层的形式。

大概流程：

```
源代码
  -> 词法分析
  -> 语法分析
  -> 语义分析
  -> 中间代码
  -> 优化
  -> 目标代码
```

我现在的理解是，编译器不是一下子把代码变成机器码，而是经过很多层“整理”和“翻译”。

几个 key：

- 词法分析：把字符变成 token。
- 语法分析：把 token 组织成语法树。
- 语义分析：检查类型、作用域等含义。
- 代码生成：把中间表示变成目标机器能执行的指令。

编译原理看起来很理论，但它其实和日常写代码关系很近。  
语法错误、类型错误、作用域、函数调用、栈，这些都能在这里找到根。
