LL 分析是从左到右读输入，做最左推导。  
LR 分析也是从左到右读输入，但做的是最右推导的逆过程。

这句话有点绕。  
我现在先把 LR 理解成：

> 一边读 token，一边把已经读到的内容归约成更大的语法结构。

## 移进和归约

LR 分析里两个核心动作：

- 移进：读入一个 token，压栈。
- 归约：栈顶若干符号符合某条产生式右部，就归约成左部。

例子：

```text
E -> E + T
T -> id
```

输入：

```text
id + id
```

可以先把第一个 `id` 移进，然后归约成 `T`，再进一步归约成 `E`。  
遇到 `+` 后继续移进，读第二个 `id`，再归约。

## 为什么 LR 强

LR 能处理的文法范围通常比 LL 更广。  
很多实际编译器生成工具使用 LR 或它的变种。

不过手工写 LR 分析器比较麻烦，因为要构造项目集和分析表。

## 冲突

LR 分析表可能出现冲突：

- 移进-归约冲突
- 归约-归约冲突

比如 `if-else` 的悬空 else 问题，就很经典。

key：

- LR 的核心动作是移进和归约。
- LR 从底向上构造语法结构。
- LR 能处理较多文法，但构造表更复杂。
