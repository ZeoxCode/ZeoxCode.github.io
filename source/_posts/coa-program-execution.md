学计算机组成，最开始要把一个直觉建立起来：

> 程序不是“自己运行”的，它最后会变成一条条指令，被 CPU 取出来执行。

以前写 C 语言：

```c
int a = b + c;
```

看起来是一句话，但机器不会直接理解这句话。它会先变成汇编，再变成机器指令。CPU 只认识非常简单的动作，比如：

- 从内存取数据
- 放到寄存器
- 做加法
- 把结果写回去

一个很粗略的过程：

```
C 代码 -> 汇编 -> 机器指令 -> CPU 取指 -> 译码 -> 执行 -> 写回结果
```

这里最重要的 key：

- **指令**：CPU 能直接执行的命令。
- **寄存器**：CPU 内部最快的小存储。
- **内存**：存放程序和数据。
- **PC**：程序计数器，保存下一条要执行的指令地址。

我觉得计组这门课其实是在回答一个问题：

> 代码写完以后，硬件到底做了什么？

操作系统会管进程、内存、文件，但再往下看，程序最终还是落到 CPU、内存、总线、I/O 这些硬件结构上。
