## SOA 基本概念

**SOA（面向服务的架构）**：将应用程序的功能作为**服务**来构建和使用，服务之间通过网络通信，松耦合。

**核心原则**：
- **服务松耦合**：服务之间最小化依赖
- **服务抽象**：隐藏实现细节，只暴露接口
- **服务可重用**：同一服务可被多个消费者使用
- **服务自治**：服务自己控制自己的环境和资源
- **服务无状态**：不保留上次调用的状态（提高可扩展性）
- **服务可发现**：服务可以通过注册中心被找到
- **服务可组合**：多个服务可以组合成更复杂的服务

## Web 服务（SOAP）

**Web 服务三要素**：

| 技术 | 作用 | 说明 |
|------|------|------|
| **WSDL** | 描述服务 | XML格式，描述服务接口、方法、参数、地址 |
| **SOAP** | 调用服务 | 基于XML的消息协议，通过HTTP传输 |
| **UDDI** | 发现服务 | 服务注册与发现（类似黄页，实际使用较少） |

**SOAP 消息结构**：
```xml
<Envelope>
    <Header>  <!-- 可选，元数据（认证、事务等） -->
    <Body>    <!-- 必须，请求或响应内容 -->
        <Fault>  <!-- 错误信息 -->
```

- SOAP 是**协议**，与传输方式无关（HTTP/SMTP/TCP）
- 强类型，契约先行（Contract First）
- 适合：企业内部集成、需要严格契约的场景

## REST

**REST（表现层状态转移）**：一种架构风格，充分利用 HTTP 协议本身的能力。

**六个约束**：
1. 客户端-服务器分离
2. 无状态（每次请求携带完整信息）
3. 可缓存
4. 统一接口（资源、HTTP方法、自描述消息、超媒体HATEOAS）
5. 分层系统
6. 按需代码（可选）

**HTTP 方法语义**：

| 方法 | 操作 | 幂等 | 安全 |
|------|------|------|------|
| GET | 获取资源 | 是 | 是 |
| POST | 创建资源 | 否 | 否 |
| PUT | 替换资源 | 是 | 否 |
| PATCH | 部分更新 | 否 | 否 |
| DELETE | 删除资源 | 是 | 否 |

**幂等**：多次调用结果相同；**安全**：不修改服务器状态

**RESTful URL 设计**：
```
GET    /users          # 获取用户列表
GET    /users/123      # 获取特定用户
POST   /users          # 创建用户
PUT    /users/123      # 更新用户（全量替换）
PATCH  /users/123      # 更新用户（部分更新）
DELETE /users/123      # 删除用户
```

## SOAP vs REST 对比

| 对比项 | SOAP | REST |
|--------|------|------|
| 协议 | 严格的协议规范 | 架构风格 |
| 消息格式 | 只支持XML | JSON、XML、HTML等 |
| 传输协议 | HTTP/SMTP/TCP | 主要是HTTP |
| 契约 | WSDL（严格） | OpenAPI/Swagger（非必须） |
| 状态 | 可有状态 | 无状态 |
| 性能 | 较低（XML解析开销） | 较高（JSON更轻量） |
| 适用 | 企业集成、金融 | Web/移动端API |

## ESB（企业服务总线）

**ESB** 是 SOA 的核心基础设施，充当服务之间的中间层：

```
ServiceA ──┐
ServiceB ──┤── ESB（总线）──┤── ServiceD
ServiceC ──┘               └── ServiceE
```

**ESB 功能**：
- **消息路由**：根据规则将消息路由到目标服务
- **协议转换**：HTTP↔SOAP↔JMS 等互转
- **数据转换**：XML↔JSON 格式转换
- **服务编排**：将多个服务组合成业务流程
- **安全**：统一认证授权
- **监控**：服务调用监控和日志

**典型产品**：MuleSoft、IBM MQ、Apache ServiceMix

## Web Services 安全

- **WS-Security**：SOAP 消息级安全（加密、签名）
- **OAuth 2.0**：授权框架（用于 REST API）
- **JWT（JSON Web Token）**：无状态认证令牌
  - 结构：Header.Payload.Signature（Base64编码）
  - 服务端无需存储Session，适合微服务

## 考试重点

- WSDL 描述什么、SOAP 传什么、UDDI 做什么
- REST 的无状态约束及其好处（可扩展性、可缓存）
- HTTP 方法的幂等性（GET/PUT/DELETE幂等，POST/PATCH不幂等）
- ESB 的作用：连接异构系统，做协议和数据转换
