TCP 是计算机网络里最重要的协议之一。
它解决的问题是：

> 如何在不可靠的 IP 网络上，提供尽量可靠的字节流传输。

## IP 为什么不可靠

IP 层只负责尽力而为地转发数据包。

它不保证：

- 包一定到
- 包按顺序到
- 包不会重复
- 包不会损坏

如果应用直接面对这些问题，会很麻烦。
所以 TCP 在 IP 之上做了一层可靠传输。

## TCP 的三个关键特点

### 1. 面向连接

通信前要先建立连接，也就是三次握手。

这里的连接不是物理线，而是双方维护的一组状态，比如序号、窗口大小、连接状态。

### 2. 可靠传输

TCP 通过序号、确认号、重传机制来保证数据可靠。

发送方发出数据后，会等待接收方确认。
如果超时没有确认，就认为可能丢包，需要重传。

### 3. 字节流

TCP 不是一条消息一条消息地交付，而是连续字节流。

比如发送方连续写：

```text
hello
world
```

接收方可能一次读到：

```text
helloworld
```

也可能分几次读到。
所以应用层要自己处理消息边界。

## TCP 解决哪些问题

TCP 大致解决：

- 可靠性：丢了要重传。
- 顺序性：乱序了要重排。
- 流量控制：别把接收方撑爆。
- 拥塞控制：别把网络撑爆。

## 经典例题

**问题：TCP 是可靠的，是否说明底层网络是可靠的？**

不是。

底层 IP 网络仍然是不可靠的。
TCP 的可靠性是通过确认、重传、排序等机制“包装”出来的。

就像快递公司不能保证路上绝对不出错，但可以通过丢件赔付、重新配送、物流记录来提高最终送达的可靠性。

## 不能忘的点

- TCP 建立的是逻辑连接，不是物理连接。
- TCP 面向字节流，不保留消息边界。
- TCP 的可靠性是靠序号、ACK 和重传机制实现的。
