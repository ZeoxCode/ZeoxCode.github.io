学完数据结构以后，再学算法设计与分析，感觉重点变了。

数据结构更像是在问：

```text
数据怎么组织？
```

算法设计更像是在问：

```text
问题怎么求解？
为什么这样求？
代价是多少？
有没有更好的方法？
```

比如同样是“找最短路径”，数据结构会关心图怎么存，邻接矩阵还是邻接表。算法会关心用 BFS、Dijkstra 还是 Floyd，为什么这个算法能得到正确答案，复杂度是多少。

## 算法课真正关心什么

我觉得有四件事：

1. 问题建模：把现实问题变成计算问题。
2. 设计策略：暴力、分治、贪心、动态规划、回溯等。
3. 正确性证明：为什么这个算法一定对。
4. 复杂度分析：时间和空间代价是多少。

以前写程序，常常只要样例跑过就觉得可以。  
算法课会继续追问：

- 所有输入都对吗？
- 最坏情况会不会很慢？
- 数据规模变大还能跑吗？
- 有没有重复计算？
- 能不能用更合适的数据结构？

## 一个小例子

求数组中两数之和是否等于 target。

最直接的暴力：

```cpp
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] + a[j] == target)
            return true;
```

时间复杂度是 `O(n^2)`。

如果用哈希表：

```cpp
for (int x : a) {
    if (set.count(target - x)) return true;
    set.insert(x);
}
```

平均时间复杂度可以到 `O(n)`。

这就是算法设计的感觉：同一个问题，不同思路，代价差很多。

## 常见设计思想

这门课后面主要围绕这些思想：

- 暴力枚举：先把最朴素的方法写出来。
- 分治：把大问题拆成小问题。
- 贪心：每一步选当前看起来最好的。
- 动态规划：保存子问题结果，避免重复计算。
- 回溯：搜索所有可能，但及时撤销和剪枝。
- 分支限界：在搜索中用边界估计减少无效分支。
- 随机化：利用随机选择降低最坏情况风险。

这些不是孤立技巧，而是不同类型问题的常见套路。

## 这门课的关键感觉

算法设计不是背代码模板。模板可以背，但更重要的是知道什么时候用。

比如：

- 看到最优子结构，可能想到 DP 或贪心。
- 看到区间合并，可能想到排序或区间 DP。
- 看到“所有方案”，可能想到回溯。
- 看到图上的最短、最小连通，可能想到图算法。
- 看到规模很大，先估复杂度能不能过。

最后要形成一种习惯：

> 先想清问题结构，再写代码。

key：

- 算法设计 = 解法 + 正确性 + 复杂度。
- 数据结构是算法的工具。
- 同一问题不同解法，性能可能差几个数量级。
